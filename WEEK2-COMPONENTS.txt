ОБЩИЕ КОМПОНЕНТЫ — FRONTEND A + FRONTEND B
Версия 0.2, предложение для согласования. Реализация без зависимостей.

Подключение
<link rel="stylesheet" href="style.css">
<script src="ui.js" defer></script>
После ui.js подключить собственный скрипт страницы. UI — общий объект в classic
script scope; импорт как ES module сейчас не используется. Стек приложения
не выбран: после согласования можно перенести тот же интерфейс компонентов.
Для демонстрации библиотеки дополнительно используются components.js и app.js.

Доступные функции
UI.button({label,href?,variant?,type?,disabled?,loading?,id?,autofocus?})
Возвращает HTML кнопки или ссылки. variant: primary / secondary / danger.
Для действия используйте кнопку; для перехода — href. Loading блокирует повтор.
href принимает внутренний hash-маршрут или локальный txt/json; внешние URL
пока не поддерживаются. Обработчик назначается после вставки в DOM.

UI.field({id,name?,label,value?,kind?,hint?,error?,placeholder?,required?,
          disabled?,min?,max?,options?})
Возвращает поле с подписью, подсказкой и сообщением об ошибке.
kind: text / email / number / textarea / select. options: [{value,label}].
id должен быть уникальным на странице. Все текстовые значения экранируются.
UI.fieldError(input,message) обновляет aria-invalid и связанный текст ошибки.
Проверки на клиенте не заменяют серверную валидацию.

UI.alert({title,message,tone?,action?})
tone: error / success / info. Ошибка имеет role=alert, остальные — role=status.
action — параметры UI.button. Не вставлять серверный HTML в сообщения.

UI.confirm({title,message,confirmLabel?,danger?}) -> Promise<boolean>
true только по кнопке подтверждения; false по отмене/Escape.
Начальный фокус — «Отмена». Tab и Shift+Tab циклически переключают две кнопки.
После закрытия фокус возвращается к вызвавшему элементу. Вызывающая форма
может затем перевести его в поле (например, после подтверждённой очистки).
Повторный вызов при уже открытом диалоге возвращает false.
Пример:
const confirmed = await UI.confirm({title:'Очистить поля?',
  message:'Название и цена будут удалены.',confirmLabel:'Очистить',danger:true});
if (confirmed) { /* выполнить локальную очистку */ }

UI.authorCard(viewModel), UI.jobCard(viewModel)
Карточки используются в главной, каталогах и библиотеке. В текущей версии
viewModel соответствует учебным объектам authors/jobs из app.js.
Это формат представления, не API DTO. Перед подключением сервера нужен адаптер:
enum площадки -> подпись; копейки -> рубли для форматирования; null -> «Пока нет данных»;
отфильтрованные каналы/услуги -> нужная карточка. Не подставлять сырой API-ответ напрямую.
Сейчас подписи выборки и города в карточках относятся к учебному набору Москвы.

UI.skeleton(), UI.catalogState(type,URLSearchParams), UI.demoBar(type,params)
Макеты для демонстрации состояния, не сетевой клиент. type: authors / jobs.
demo=loading|empty|error. Отсутствие demo показывает обычные учебные данные.
Повтор удаляет только demo из URL, сохраняя площадку и бюджет.

Оформление и доступность
Общие токены: --ink, --muted, --paper, --line, --lime, --purple,
--danger, --error-bg, --success-bg, --focus.
Текст 16 px, вторичные подписи 14 px, кнопки высотой от 48 px.
Есть видимый focus-visible, подписи полей, связанные ошибки, native dialog.
Анимация индикаторов отключается при prefers-reduced-motion.
Сетка перестраивается на 650/850/950 px; таблица API прокручивается внутри контейнера.

Распределение — на согласование
Frontend A: первичная версия библиотеки, публичные страницы, состояния каталогов.
Frontend B: проверка применения в кабинетах, формы заказа, дополнительные состояния.
Backend A: schema данных и ошибок. Бизнес-ограничения не задаются UI-библиотекой.
Команда подтверждает правила изменения общей библиотеки и владельца каждого компонента.
