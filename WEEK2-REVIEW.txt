НЕДЕЛЯ 2 — ОБЩИЕ КОМПОНЕНТЫ И API
Роль: Frontend A, разработчик 3.
Основание: «Задачи_и_рекомендации_команде.md», раздел разработчика 3, неделя 2.

Что сделано
1. Общие кнопки: основная, второстепенная, опасное действие, disabled, ожидание.
2. Поля: text/email/number/select/textarea, подсказки и ошибки, required/disabled.
3. Общие карточки автора и рекламного задания вынесены из app.js в ui.js.
4. Сообщения: ошибка, успех, информация; общий формат отображения.
5. Окно подтверждения: отмена, подтверждение, Escape, управление фокусом.
6. Макеты загрузки, пустого результата, ошибки и данных для двух каталогов.
7. Общие поля и кнопки используются в фильтрах реальных страниц прототипа.
8. Подготовлены контракт API, фильтры, формат ошибок, ограничения,
   пример JSON, инструкция подключения и вопросы для согласования.

Где посмотреть
Открыть dist/index.html и ссылку «Компоненты и состояния» внизу страницы.
Прямой маршрут: #components.
Состояния: #components?view=states; контракт: #components?view=api.
Онлайн после публикации: https://blogger-week-one-ak-1125.nynastyyyy.chatgpt.site/#components

Проверки
Программно: 10 проверок первой недели и 7 проверок второй; все прошли.
Повтор: node check.cjs; node check-week2.cjs. Нужен установленный Node.js.
Проверка синтаксиса: node --check dist/ui.js, components.js, app.js.
В браузере проверены:
— пустое название/отрицательная цена, ошибки полей, исправление и успех;
— отмена очистки, Escape и подтверждённая очистка;
— начальный фокус, Tab/Shift+Tab внутри диалога и возврат фокуса;
— ошибка каталога и повтор, загрузка, пустая подборка и сброс;
— библиотека и API на ширине 390 px: без горизонтального переполнения;
— окно подтверждения на мобильном экране помещается по ширине;
— при ширине 1440 px scrollWidth=innerWidth, переполнения страницы нет.
Во время проверки исправлен выход фокуса по Tab из последней кнопки диалога.
Визуальные примеры сохранены в evidence/week2-mobile.png и week2-dialog.png.
Полная кроссбраузерная и скринридерная проверка ещё не проводилась.

Что является макетом
Состояния ошибки/загрузки включаются через demo в URL, сеть не вызывается.
Форма библиотеки демонстрирует валидацию и диалог, профиль не создаётся.
Ограничения названия/цены в ней учебные, не утверждённые бизнес-правила.
Контракт API — предложение, а не описание работающего backend.
